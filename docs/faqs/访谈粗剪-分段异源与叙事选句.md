# 访谈粗剪：分段异源与叙事选句

本场踩坑来源：刘探书访谈粗剪（选型「不用模板」；交付 `CS-01`～`CS-10` 等多方向）。  
目标：下一场同类粗剪先保效果；多路并行时压掉父 agent 修刀返工。程序化（合并 STT 升格 / 叙事 cut 升格 / 放宽 timeline 升序）**未做**，验证后再考虑。

## 适用

- 访谈 / 人物叙事初剪，不是峰会关键词高光。
- 片源常为「前半单机 + 后半同步双机」或其它时段不一致的多文件。
- 用户给了精剪方案：只当**时长预算 + 检索词**，不做标题卡 / 图卡 / 履历播报。

## 同素材续剪（口语即可）

用户通常只说：「以前剪过，是刘探书」/「同素材再做一条」。**不要求**用户说 theme 路径或「复用 sources」。

Agent 开剪前：

1. 扫 `temp/*/sources.md`、`sources.json`（`person` / `parts`）、`output/CS-*`。
2. **唯一命中** → 读 `sources.md` + 按 `stt` 溯源复用转写，继续。
3. **对不上 / 多候选** → **停下来问一句确认**，再动。
4. 默认不重 STT、不当全新采访。

首次用户讲清三片关系时：当场写 `temp/<素材主题>/sources.md`，并在 `sources.json` 写 `layout` + `stt`；禁止只留在聊天里。

## temp 目录命名（抗碰撞）

两类目录分开：

| 类型 | 是否打戳 | 例子 |
|---|---|---|
| **素材枢纽**（sources + 合并转写 + aligned concat） | **否**，长期稳定供续剪扫到 | `temp/刘探书访谈OPC` |
| **成片工作区**（timeline / cut 脚本 / 本场字幕） | **是**：`{短名}_{YYYY_MM_DD_HH_MM}`（Asia/Shanghai）；同分钟碰撞加 `__2` | `temp/刘探书访谈CS04_2026_09_10_17_50` |

- 新建成片工作区：用 [`src/lapi/theme_dir.py`](../../src/lapi/theme_dir.py) 的 `allocate_temp_dir`（`plan` / Agent 手动建目录同此约定）。
- 续剪 / cut / dump：短名即可，`resolve_temp_dir` 取该短名下**最新**戳目录。
- **`output/` 交付名不打戳**（如 `output/CS-04 互远AI官方/`）。
- cleanup `--theme` **须写精确目录名**（含戳），不做短名解析，避免误扫枢纽。

## STT：优先分段；合并须可找回（别重复花钱）

**优先：** 对原始各段算 MD5 → 查/写 `cache/transcripts/<md5>.json` → 按 `T0` 合成工作区 `transcript.json`（刘探书）。

**若已对合并片 STT（如可可 `source_concat`）：** 保留 cache；必须在 `sources.json.stt` 登记 concat md5、`from_parts`、原片路径，使下次用人物名/原片也能命中，禁止当「没转过」重跑。

开剪前查 cache 顺序：

1. 各 `stt.parts[].md5`
2. `stt.concat.md5` / `transcript_md5`
3. 工作区 `transcript.json` / `merged_transcript`
4. 全无 → 才打 API（优先分段，并写回溯源）

尽量不要新场「先拼再 STT」；历史合并转写必须可发现。

## temp / cache 性价比

**永久保留：** `cache/transcripts/`、`sources.md`、`sources.json`（含 stt）、合并 `transcript.json`、`timeline.json`、`review_script.md`、`*_concat.txt`、`cut_narrative.py`、已纠错 `highlight_*.srt`

**交付后可删（大、重建便宜）：** `aligned/*.mp4`、`source_concat.mp4`、`cuts/`、`narrative/`、`jinju/_bake/`、`jinju/_preview/`、`jinju/*.mp4`、临时 `audio.*.mp3`、冗余 `*_part1`/`*_part2` 目录

同日多批续剪：成片区 `cuts/`/`narrative/` 可批批清；枢纽 `aligned/*.mp4` **可留到当日最后一批再清**（见下「多路 subagent 并行续剪」）。

清理入口（交付初检后**必须**跑）：[`docs/workflows/cleanup-temp-media.md`](../workflows/cleanup-temp-media.md) → `.venv/bin/python scripts/cleanup_temp_media.py`（默认 dry-run；`--apply` 才删）。

## 检查清单（按序）

### 0. 复用发现

- [ ] 若用户说「剪过 / 同人」：先扫 sources / output；不确定则问。
- [ ] 有 `sources.md` 则先读；STT 前按上节四步查 cache。

### 1. 片源形态与对齐

- [ ] 搞清：哪几段是完整音频轴、哪几路仅后半有特写；**写入 `sources.md`**。
- [ ] cut 只认一对 `wide` / `closeup` → 需要时做虚拟双机：
  - `aligned_wide` = 前半全景 + 后半全景
  - `aligned_closeup` = 前半全景垫 + 后半特写（禁止臆造真特写）
- [ ] 记下分界 `T0`（前半时长）；**禁止跨 `T0` 选段**。
- [ ] `timeline.audio_source = wide`（完整音频轴在全景上时）。

### 2. 转写

- [ ] **跳过** `run_dualcam_lapi.py plan` 的规则导演（峰会粗筛会打乱人物叙事）。
- [ ] **优先**分别 STT 两段**全景**原片（与音源一致），后半词级时间码 `+ T0` 合并进一份 `transcript.json`；md5 写入 `stt.parts`。
- [ ] 不要对「假特写前半」单独做 STT。
- [ ] 若用合并片 STT：登记 `stt.concat`；删大文件后仍能靠 md5 找回 cache。

### 3. 结构与选句（效果核心）

- [ ] 全片只立一句中心句；案例只证明它；不另开第二主题。
- [ ] 精剪方案 → 段落时长预算 + 关键词表；粗剪不做标题卡 / 关键词上屏 / jinju 焊尾。
- [ ] **先关键词打点，再 dump 词窗锁边**；禁止无目标通读整场转写。
- [ ] 词级起止：句首句尾完整；禁半截（如「都觉得」「变成了」起刀）。
- [ ] 优先被访第一人称；少留主持人问句。
- [ ] 可一次按段落写出候选表再微调时长，减少来回试切。

### 4. 镜头

- [ ] `t < T0`：**只能 `wide`**。
- [ ] `t ≥ T0`：主特写、辅全景（定场 / 三人关系可用全景）。
- [ ] 单镜建议 ≥ 2.5s；不句中硬切。

### 5. 出片契约（本仓现状）

- [ ] `load_timeline` **要求源时间升序、段不重叠**。
- [ ] 叙事需要跳切重排时：勿直接 `run_dualcam_lapi.py cut`（会报乱序）。
- [ ] 本场一次性绕过：`temp/刘探书访谈OPC/cut_narrative.py`（**未升格**；同类再跑通后再考虑进 `scripts/`）。
- [ ] 段已按源时间升序时，才可用标准 `cut`。

### 6. 闸门与交付

- [ ] 交稿前跑 `scripts/check_interview_timeline.py --theme <戳名>`（退出 0）。
- [ ] 先写 / 改 `review_script.md`，**人过目后再 cut**（勿被「做完 todo」冲掉确认）。
- [ ] 字幕：只改别字，**不动时间码 / 不增删 cue**；已知 ASR 表一次替换。
- [ ] 访谈默认 **跳过** `run_jinju.py`。
- [ ] 工作区 theme 可与交付名分离：例枢纽 `temp/刘探书访谈OPC` + 成片区 `temp/刘探书访谈CS04_2026_09_10_17_50` → `output/CS-04 互远AI官方/`；同素材多方向用 `CS-02…`（成片 temp **必打东八区戳**）。
- [ ] 交付后**必须**跑 [`cleanup-temp-media`](../workflows/cleanup-temp-media.md)（dry-run → `--apply`）；勿删 cache / sources.md / 转写；同日还有下一批则枢纽 aligned 可留到批末。

## 多路 subagent 并行续剪

踩坑来源：同素材一次开多路（如 CS-07～10）并行选句时，墙钟大头常是**父 agent 串行修半截 / 压时长**，不是 ffmpeg。并行已覆盖选句与 cut；要提速就压掉父 QA 返工。

### 职责划分

| 角色 | 做一次 / 并行 | 产物 |
|---|---|---|
| **父 agent（串行）** | 扫枢纽、复用转写、按需重拼 `aligned/*.mp4`、`allocate_temp_dir` 建 N 个成片区、写各区 `sources.json`、给每条脚本锚点秒级区间 | 共享准备完成后再开 N 个 subagent |
| **Subagent（并行，一路一条）** | 只改自己的 `temp/<戳>/`：关键词打点 → dump 锁边 → `timeline.json` + `review_script.md` + `cut_cs0x.py`；**禁止 cut、禁止重 STT、禁止改对方目录、禁止改 `src/`** | 交稿前自跑验收（见下） |
| **父 agent（串行，应极短）** | 对每路跑同一验收脚本；失败才 `resume` 该路；禁止整批手工 dump | 合格后再并行 cut / pack |
| **Cut（并行）** | 各跑 `cut_cs0x.py`；字幕别字按「已知 ASR 替换表」一次改完再 pack | `output/<交付名>/` |

### 交稿验收（机器门，交稿前必过）

```bash
.venv/bin/python scripts/check_interview_timeline.py --theme <戳名或短名>
```

默认检查：合计时长 vs `target_seconds`（可用 `--tolerance`）、禁止单段跨 `T0`、`t < T0` 只能 `wide`、段起/止词半截启发式。退出码非 0 → 未交稿。

### 半截句修法（默认）

**在预算内挪到最近完整句界**（dump 词窗锁边）。宁可删段 / 换锚点，**禁止**为补全句无限向前吞词把总时长撑爆（曾出现修半截后 40s 目标胀到 60s+）。

常见半截起刀（验收会标）：以「，」「然后」「的」「他成为」「哪些」等接上句中段起刀。

### 同日多批：aligned 批末再清

同日还要对同一枢纽开下一批 CS 时：**本批交付后可清各成片区 `cuts/` / `narrative/`，但枢纽 `aligned/*.mp4` 可留到当日最后一批再 cleanup**，避免每批 ffmpeg 重拼约 8GB。最后一批（或明确「今日停剪」）再对枢纽 `--apply`。

成片区 cleanup `--theme` 仍须精确戳名；勿误清枢纽转写 / `*_concat.txt`。

### 已知 ASR 替换表（写 SRT / 审阅摘录时一次做）

| ASR | 正确 |
|---|---|
| 流动官 | 运行官 |
| 先进带动后，后退 / 后退啊 | 先进带动后进 |
| 信息的大运工 / 大运工 | 信息的搬运工 / 搬运工 |
| 信息繁荣 | 信息繁冗 |

字幕：只改别字，**不动时间码 / 不增删 cue**。计划里已列的别字不要等 cut 后再「发现」。

### Subagent prompt 必写硬约束（摘要）

- 目标时长 ± 容差；dump 锁边；禁半截、禁跨 `T0`
- P1 仅 `wide`；`audio_source=wide`
- 交稿前：`check_interview_timeline.py --theme <本路戳名>` 退出 0
- 第 5 拍无原声评论引导 → 不切；后期说明写入 `review_script` / `stats.late_note`
- 粗剪不做标题卡 / 评论卡 / 结构图
